# Requirements Document

## Introduction

Deforestation Watch Nepal is a fully responsive, static GIS intelligence dashboard for governments, researchers, NGOs, conservation organizations, and environmental scientists. The platform visualizes Nepal's forest cover, deforestation trends, district-level data, satellite-based GIS maps, AI-driven risk predictions, and environmental insights — all powered by pre-generated data files (CSV, JSON, GeoJSON, PNG) fetched at runtime. No backend, database, or authentication is involved. All analysis is assumed to be pre-processed by Python scripts whose outputs are consumed by the dashboard.

The technology stack is strictly HTML5, CSS3, Vanilla JavaScript (ES6 Modules), TailwindCSS CDN, Leaflet.js, Chart.js, Font Awesome, and Google Fonts (Inter). The visual language references Global Forest Watch, Google Earth Engine, ArcGIS Dashboard, Apple, Vercel, and Linear: generous whitespace, premium typography, deep forest green accents on light neutral backgrounds.

## Glossary

- **Dashboard**: The Deforestation Watch Nepal single-page web application.
- **GIS_Map**: The interactive Leaflet.js map that is the centerpiece of the Dashboard.
- **Time_Explorer**: The interactive timeline component spanning years 2015–2026.
- **Prediction_Dashboard**: The section visualizing Python-generated AI deforestation risk prediction data.
- **Before_After_Slider**: The interactive image comparison component showing satellite imagery for 2018 vs. 2025.
- **Download_Center**: The section providing downloadable CSV, GeoJSON, PNG, and PDF assets.
- **Analytics_Dashboard**: The section containing all Chart.js-based charts and dynamic year filtering.
- **Environmental_Insights**: The section displaying auto-generated insight cards derived from loaded data.
- **Statistics_Cards**: The row of animated counter cards showing aggregate forest metrics.
- **Data_Loader**: The JavaScript module responsible for fetching all external JSON, GeoJSON, and CSV files.
- **Forest_Layer**: A GIS_Map overlay showing forest cover extent for a given year.
- **Loss_Layer**: A GIS_Map overlay showing areas of forest loss.
- **Gain_Layer**: A GIS_Map overlay showing areas of forest gain.
- **Protected_Areas_Layer**: A GIS_Map overlay showing legally protected forest boundaries.
- **Admin_Boundaries_Layer**: A GIS_Map overlay showing Nepal's administrative district boundaries.
- **District**: One of Nepal's 77 administrative districts, each having associated forest metrics.
- **Risk_Score**: A numeric value (0–100) generated by the Python prediction model representing deforestation risk for a District.
- **Prediction_Confidence**: A percentage value indicating the reliability of the AI prediction model for a given District or year.
- **Viewport**: The visible area of the browser window.
- **Section**: A full-width horizontal band of the Dashboard page (e.g., Hero, Statistics, Map, etc.).
- **Responsive_Layout**: A layout that adapts correctly to desktop (≥1280px), laptop (1024–1279px), tablet (768–1023px), mobile (320–767px), and large display (≥1536px) breakpoints.
- **CDN**: Content Delivery Network — all third-party libraries are loaded via CDN links.
- **ES6_Module**: A JavaScript file using `import`/`export` syntax.
- **Fetch_Request**: A browser `fetch()` call to load a local data file.
- **Particle_Animation**: A subtle floating-dot animation rendered on the Hero Section canvas.
- **Counter_Animation**: A numeric count-up animation applied to Statistics_Cards on first viewport entry.
- **Reveal_Animation**: A CSS/JS-driven fade-and-slide entrance animation triggered when a Section enters the viewport.

### Requirement 1: Project File Structure and Static Delivery

**User Story:** As a developer, I want all dashboard files organized in a defined structure, so that the project is maintainable, deployable from any static file host, and consistent with the specified architecture.

#### Acceptance Criteria

1. THE Dashboard SHALL be deliverable as a set of static files with no server-side runtime dependency.
2. THE Dashboard SHALL organize files according to the following structure: `index.html`, `css/style.css`, `css/animations.css`, `css/responsive.css`, `js/main.js`, `js/map.js`, `js/dashboard.js`, `js/charts.js`, `js/prediction.js`, `js/loader.js`, `js/ui.js`, `js/utils.js`, `data/statistics.json`, `data/prediction.json`, `data/risk_score.json`, `data/district.geojson`, `data/forest.geojson`, `assets/images/`, `assets/icons/`, `assets/videos/`, `README.md`.
3. THE Dashboard SHALL load all third-party libraries (TailwindCSS, Leaflet.js, Chart.js, Font Awesome, Google Fonts Inter) exclusively via CDN links in `index.html`.
4. THE Dashboard SHALL use ES6_Module syntax (`import`/`export`) for all JavaScript files.
5. THE Dashboard SHALL NOT use React, Vue, Angular, Next.js, Bootstrap, jQuery, Node.js, or any backend framework.

### Requirement 2: Data Loading and Data-Driven Rendering

**User Story:** As a developer, I want the dashboard to load all data from pre-generated files using `fetch()`, so that no values are hardcoded and the UI always reflects the current dataset.

#### Acceptance Criteria

1. THE Data_Loader SHALL fetch `data/statistics.json` on page load and supply its values to the Statistics_Cards and Environmental_Insights sections.
2. THE Data_Loader SHALL fetch `data/prediction.json` on page load and supply its values to the Prediction_Dashboard section.
3. THE Data_Loader SHALL fetch `data/risk_score.json` on page load and supply its values to the Risk_Score heat map and Top 10 High Risk Districts list.
4. THE Data_Loader SHALL fetch `data/district.geojson` on page load and supply it to the GIS_Map as the Admin_Boundaries_Layer and District popup data source.
5. THE Data_Loader SHALL fetch `data/forest.geojson` on page load and supply it to the GIS_Map as the Forest_Layer, Loss_Layer, and Gain_Layer data source.
6. IF a Fetch_Request fails, THEN THE Data_Loader SHALL display a non-blocking error notification identifying which file failed to load, without crashing the remainder of the Dashboard.
7. THE Dashboard SHALL NOT hardcode any forest area, loss, gain, risk, or prediction numeric values — all displayed numbers SHALL be derived from fetched data files.

### Requirement 4: Statistics Cards Section

**User Story:** As a researcher, I want a row of animated metric cards showing key forest statistics, so that I can quickly grasp the scale of Nepal's forest situation.

#### Acceptance Criteria

1. THE Statistics_Cards Section SHALL display the following seven metrics: Forest Cover (hectares), Forest Loss (hectares), Forest Gain (hectares), Protected Areas (count), Districts (count), Satellite Images (count), Prediction Accuracy (percentage) — all sourced from `data/statistics.json`.
2. WHEN a Statistics_Card first enters the Viewport, THE Statistics_Cards Section SHALL play a Counter_Animation that counts up from zero to the final value over a duration between 1500ms and 2500ms.
3. THE Statistics_Cards Section SHALL display an appropriate icon (Font Awesome) and a descriptive label for each metric card.
4. THE Statistics_Cards Section SHALL use the defined color system: primary forest greens for positive metrics, warning amber for loss metrics, and info blue for neutral metrics.
5. IF `data/statistics.json` has not yet loaded, THEN THE Statistics_Cards Section SHALL display skeleton placeholder elements of equivalent dimensions until data is available.

### Requirement 5: GIS Map (Centerpiece)

**User Story:** As a GIS analyst, I want an interactive full-width map of Nepal with multiple toggleable layers, so that I can spatially explore forest cover, loss, gain, and district risk data.

#### Acceptance Criteria

1. THE GIS_Map SHALL render using Leaflet.js within a container occupying the full width of the content area and a minimum height of 600px on desktop.
2. THE GIS_Map SHALL provide two base tile layers selectable by the user: OpenStreetMap and a satellite imagery tile layer.
3. THE GIS_Map SHALL provide the following toggleable overlay layers: Forest_Layer, Loss_Layer, Gain_Layer, Protected_Areas_Layer, Admin_Boundaries_Layer — each controllable via a Layer Switcher control.
4. THE GIS_Map SHALL center on Nepal's geographic center coordinates and set an initial zoom level that fits Nepal within the map container on desktop.
5. THE GIS_Map SHALL display a map legend identifying the color encoding for each active overlay layer.
6. THE GIS_Map SHALL display standard Leaflet controls: zoom in/out, scale bar, and attribution.
7. THE GIS_Map SHALL provide a Fullscreen button that expands the map container to cover the full Viewport; activating Fullscreen again SHALL restore the original layout.
8. THE GIS_Map SHALL provide a Reset View button that returns the map to the initial center coordinates and zoom level.
9. THE GIS_Map SHALL provide a District Search input; WHEN the user types a district name and selects a result, THE GIS_Map SHALL pan and zoom to that District and highlight its boundary.
10. WHEN the user hovers over a District polygon, THE GIS_Map SHALL highlight that polygon with a distinct border color and increased border width.
11. WHEN the user clicks a District polygon, THE GIS_Map SHALL display a popup containing: District name, Forest Cover (ha), Forest Loss (ha), Forest Gain (ha), Risk_Score, Prediction Risk level (Low/Medium/High/Critical), and Forest Cover Trend for the selected year.
12. THE GIS_Map SHALL update the visible Forest_Layer, Loss_Layer, and Gain_Layer data when the Time_Explorer year selection changes.
13. THE GIS_Map SHALL be keyboard-navigable, with ARIA labels on all custom controls.

### Requirement 21: Parser and Data File Contracts

**User Story:** As a developer, I want the data file formats to be strictly defined, so that the Python analysis pipeline and the dashboard frontend remain compatible without manual coordination.

#### Acceptance Criteria

1. THE `data/statistics.json` file SHALL conform to a schema where the top-level object contains: `forestCoverHa` (number), `forestLossHa` (number), `forestGainHa` (number), `protectedAreasCount` (number), `districtsCount` (number), `satelliteImagesCount` (number), `predictionAccuracyPct` (number), and a `yearlyData` array of objects each containing `year` (integer), `forestCoverHa`, `forestLossHa`, `forestGainHa`.
2. THE `data/prediction.json` file SHALL conform to a schema where the top-level object contains a `districts` array, each element having: `name` (string), `riskScore` (number 0–100), `riskLevel` (one of "Low", "Medium", "High", "Critical"), `confidencePct` (number), and a `projectedCover` array of objects with `year` (integer) and `forestCoverHa` (number).
3. THE `data/risk_score.json` file SHALL conform to a schema where the top-level object contains a `districts` array, each element having: `name` (string), `riskScore` (number 0–100).
4. THE `data/district.geojson` file SHALL conform to GeoJSON FeatureCollection format, where each Feature's `properties` object contains at minimum: `name` (string), `forestCoverHa` (number), `forestLossHa` (number), `forestGainHa` (number), `riskScore` (number).
5. THE `data/forest.geojson` file SHALL conform to GeoJSON FeatureCollection format, where each Feature's `properties` object contains at minimum: `type` (one of "cover", "loss", "gain"), `year` (integer), and `areaHa` (number).
6. FOR ALL valid `statistics.json` files, parsing the file then serializing the `yearlyData` array back to JSON and re-parsing SHALL produce an array equivalent to the original (round-trip property).
7. FOR ALL valid `prediction.json` files, every `riskLevel` value SHALL be derivable from the corresponding `riskScore` using the rule: 0–39 → "Low", 40–59 → "Medium", 60–79 → "High", 80–100 → "Critical".
